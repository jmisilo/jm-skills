How the copy button swaps its icon

The Copy Page button on interfaces.dev shows a copy icon. Press it and the icon turns into a checkmark; two seconds later the checkmark turns back into the copy icon.3

The checkmark is the confirmation. Copying to the clipboard leaves nothing on screen, so the button has to say that it worked. The hard part is the icon swap itself. React replaces one icon with the other in a single frame, which reads as a flicker, and the old icon is gone before anything can animate it out.

The fix is four small decisions in Motion, an animation library for React, and each section below takes one of them. Here is the whole effect on one timeline.

Before you start

00
Mount, unmount
React adds an element to the page (mounts it) and removes it (unmounts it). Unmounting is instant, so by default nothing can animate out.
Key
The identity React gives an element. Change the key and React treats it as a new element: the old one unmounts and a new one mounts.
Exit animation
An animation that plays as an element leaves. Motion's AnimatePresence keeps a removed child on the page until its exit animation has finished.1
Spring
Motion driven by a simulated spring instead of a fixed curve. In Motion you can set it with bounce and duration.2

The icon is keyed on state

01

The button holds one piece of state, idle or active. Inside it sits a single m.span, Motion's animated span imported in its lighter m form, which takes that state as its key. When the state flips, React sees a new key, so it unmounts the old span and mounts a new one. AnimatePresence wraps the span, notices the removal and keeps the old span on screen until its exit animation ends.1

Exit is enter in reverse

02

Both swaps run one animation in two directions. The outgoing icon fades to opacity: 0, shrinks to scale: 0.25 and blurs to 4px. The incoming icon starts from those values and returns to normal.3 At this size the blur hides the moment where the two shapes cross, so the eye reads one icon turning into another.

popLayout keeps one slot

03

In the default mode, mode="sync", the leaving and arriving icons both sit in the layout while they overlap, so for 300ms the button holds two icons side by side and grows wider. In popLayout mode the exiting element is popped out of the layout with absolute positioning, so the new icon takes the slot at once and the old one fades out on top of it.1 It comes with two conditions: the button needs a position other than static, and a custom component child has to forward its ref.1

A spring with no bounce

04

The transition is a spring with bounce: 0 and duration: 0.3, in seconds, since that is the unit Motion takes. A bounce of 0 is critically damped: the value rises fast and settles without overshoot, so the icon never grows past full size.2 From those two numbers Motion solves for a spring of about stiffness 947 and damping 62, which is 99% of the way there at 216ms. Last, initial={false} on AnimatePresence skips the enter animation on the first render, so the icon is simply there when the page loads.1

What it comes down to

05

One idea carries the whole effect: turn the swap into a remount, then animate the remount. The key makes the change a remount, AnimatePresence gives the leaving icon time to go, popLayout keeps both in one place, and a quiet spring times it.

The same recipe works for any icon with two states, such as play and pause or mute and unmute:

  1. Key the icon on state. One m.span inside AnimatePresence, with key={state}.
  2. Pop the leaver out of layout. Set mode="popLayout" and give the button a position.
  3. Mirror enter and exit. Out to opacity 0, scale 0.25, blur 4px; in by the reverse.
  4. Use one quiet spring. bounce: 0, duration: 0.3, and initial={false} so nothing plays on load.
  5. Time the way back. A timer sets the state back to idle after 2000ms.

Limits. This page reads the effect from the interfaces.dev description and the Motion docs, not from the site's source, so the timer and the spring constants are inferred. A blur filter costs more to paint than opacity or scale, which is fine for one small icon but not for a long list. Under reduced motion, a plain fade is the safer swap.
